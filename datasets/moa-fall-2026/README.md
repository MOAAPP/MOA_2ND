# MOA 2026년 가을 공통 합성 데이터 v1

**기간:** 2026-09-11 ~ 2026-12-11 (양끝 포함 92일, Asia/Seoul, KRW)  
**규모:** 10명 × 92일 = 일별 시나리오 920행  
**성격:** 100% 인공 합성 데이터. 실제 금융거래, 실사용자 통계, 예측 모델 성능의 실증 근거가 아닙니다.

## 팀원별로 바로 사용하기

이 폴더에는 스키마·검증 설정과 생성 스크립트가 포함돼요. 전체 원본 CSV·JSON은 프로젝트 루트에서 `python3 scripts/generate_fall_2026.py .` 명령으로 생성하거나 팀 공유용 ZIP에서 받으면 됩니다. 대용량 원본은 GitHub에 불완전한 조각으로 업로드하지 않았어요. 프론트는 `public/data/moa-fall-observed.json.gz`로 관측 거래 10명치를 포함합니다.

| 파일 | 목적 | 주의 |
| --- | --- | --- |
| `metadata.json` | 기간, 분할, 시드, 원칙 | 데이터 계약 |
| `profiles.json` | U01~U10 시나리오, 고정결제·예정 입금, 기준 잔액 | 프론트 일정 표시 |
| `observed_transactions.csv` | 11/03까지 관측·기록된 합성 거래 726건 | 모델 **입력** 후보. 날짜 기준으로 잘라 사용 |
| `daily_truth.csv` | 920행 일별 합성 실제 지출·잔액·부족 정답 | 평가용 정답. 모델 입력에 사용 금지 |
| `future_scenario_transactions.csv` | 11/04~12/11 미래 가상 거래 573건 | 개발/시뮬레이션 전용, 실제 관측 기록으로 사용 금지 |
| `validation.json` | 파일 생성 결과 건수 | 무결성 검사 |
| `../../public/data/moa-fall-observed.json.gz` | **프론트에서 압축 해제해 읽는 10명 전체 관측 스냅샷** | 미래 정답 데이터 없음 |

### 데이터 분할

- 학습 구간: 9/11~10/20 (40일) / 검증 구간: 10/21~11/03 (14일)
- 미래 테스트 시나리오: 11/04~12/11 (38일) — **2026-11-04 현재 실제 관측된 내용이 아닙니다.**
- 사용자의 실제 기록이 없어 10명 모두 합성 프로필입니다. 사용자 수, 부족 탐지율, AI 정확도 등의 대외 성과 지표로 보고하지 마세요.

### 결제계좌 원장 규칙

- `income`은 결제계좌에 플러스.
- `fixed`와 `card_payment`는 결제계좌에서 마이너스.
- `spend + debit`은 결제 즉시 마이너스.
- `spend + credit`은 당일 **소비 통계에만** 반영, 다음 달 14일 `card_payment`로 결제계좌 차감. 중복 차감하면 안 됩니다.
- `spend + cash`는 결제계좌 영향 없음.
- `account_effect` 컬럼을 참조하세요. 음수 잔고는 **합성 부족 시나리오**이며 현실 계좌에 허용된 마이너스 통장이라는 뜻이 아닙니다.

### 예측·ML 데이터 누출 금지

1. 학습/검증의 기준일 `as_of` 이후 거래를 모델에 전달하지 마세요.
2. 기록이 없는 날 `has_observation=0`은 **0원 지출이 아닙니다.** `observed_spending_krw`이 빈칸으로 표시됩니다.
3. `actual_spending_krw`, `true_close_balance_krw`, `shortfall_on_essential`은 정답/평가 전용입니다. 훈련 표적 구성은 가능하지만 해당 시점 예측의 입력 피처로 쓰면 데이터 누출입니다.
4. `observed=0` 이벤트는 사용자가 놓친 합성 기록입니다. 앱에서는 관측된 거래만 로드합니다.
5. 11/04 이후 미래 시나리오를 '장래 예측이 맞았다'는 실험 결과로 제시하지 마세요.
6. 같은 사용자/날짜로 학습·검증을 섞지 마세요. 모델 선택은 10/20 이전, 검증은 10/21~11/03에 진행합니다.

### FastAPI 팀원 연동 계약 (예시)

- `POST /forecast` 입력: `{from,to,today,dailySpend,history:[{date,amount,category,from}]}`
- 응답: `{engine:"model",basis:"history",historyCount,historyDays,personalWeight,days:[{date,p10,p50,p90}],dummy:true}` (실제 코드에서는 API 검증 및 fallback 확인)
- **모델 연결 전에도 프론트는 현재 규칙 기반 모델로 동작**합니다. DB 없이 정적 JSON만 읽습니다.
- 현지 날짜 기준, 단위 KRW 정수, 합성 여부 `dummy=true` 유지. 금융 자문이 아닌 테스트입니다.

### 파일 재생성

```bash
python3 scripts/generate_fall_2026.py .
npm test && npm run typecheck && npm run build
```

시드가 고정돼 동일 소스/환경에서 동일 건수와 거래가 생성됩니다. 모든 파일을 재생성하려면 위 명령을 실행하세요.

### 프론트 확인

새 사용자에서 **예시로 먼저 둘러보기**를 선택하면 U03 데이터를 기본 사용합니다. 온보딩 마지막 화면의 접힌 `팀 테스트용 예시 시나리오 선택`을 펼쳐 U01~U10을 선택할 수 있습니다. 가계부의 9~11월 과거 거래와 결제계좌 예정 일정은 해당 사용자의 스냅샷으로 표시합니다. 11/04~12/11의 가상 **미래 거래 정답은 프론트에 들어가지 않습니다.**
