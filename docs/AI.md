# 모아 AI 설계 (v18)

> 논문에서 "AI를 쓰는 소비 의사결정 서비스를 어떻게 만들었는가"를 설명하기 위한 문서.
> 지금은 **모델 연결 없이 예시 응답**으로 동작하고, 환경변수 하나로 실제 모델로 바꿀 수 있게 만들었다.

## 1. 원칙: 계산은 코드, 말은 AI
| 역할 | 누가 | 이유 |
|---|---|---|
| 금액·날짜·이자·세금 계산 | 앱 코드(순수 함수 + 테스트) | 돈 숫자는 틀리면 안 된다. 재현 가능해야 한다 |
| 숫자를 사람 말로 풀기, 상황 짚기 | AI | 같은 숫자도 "지금 이 사람"에게 맞는 말이 필요하다 |
| 사람이 쓴 글(카드 문자·메모) → 구조 데이터 | AI | 형식이 제각각이라 규칙만으로는 끝이 없다 |

AI에는 **계산이 끝난 숫자만** 넘긴다(`src/lib/ai/context.ts`). 서버는 응답에 입력에 없던 금액이 나오면 버린다(`numbersGrounded`, 입력 숫자끼리의 합·차는 허용).

## 2. AI 작업 6개 (`shared/aiPrompts.ts`)
| 작업 | 화면 | 입력(요약) | 출력 |
|---|---|---|---|
| `brief` | 홈 맨 위 "오늘의 브리핑" | 이번 달 쓸 수 있는 돈, 남은 날, 이번 달·지난달 지출, 가장 큰 카테고리, 참은 횟수·금액, 다음 고정지출 | 제목·한 줄·추천 행동 1개 |
| `coach` | 사기 전 비교 "AI 코치" | 품목·카테고리·가격·빈도, 사면 남는 돈, 결제일 잔고, 1년 차이, 같은 카테고리 이번 달 지출·30일 횟수 | 톤(ok·careful·warn)·메시지·현실적인 팁 |
| `ledgerSummary` | 가계부 "이번 달 정리" | 월 합계, 지난달 같은 기간, 카테고리 상위 5개, 요일별 평균 최대, 가장 큰 지출 | 제목·요점 2~3개 |
| `parseSpend` | 가계부 "문자로 한 번에" | 붙여넣은 글, 오늘 날짜 | 지출 목록(날짜·금액·가게·카테고리·확신도), 뺀 줄 수 |
| `categorize` | 지출 쓰기 시트 | 품목 이름, 카테고리 목록 | 카테고리·확신도·이유 |
| `ask` | 모아 AI 물어보기(채팅) | 질문 + 내 숫자(쓸 수 있는 돈, 이번 달 지출, 상위 카테고리, 지킨 돈, 참기 비율, 목표) | 답변 3~4문장 + 이어 물을 질문 2개 |

각 작업마다 시스템 프롬프트, 출력 JSON 형식, 최대 토큰을 정의했다. 공통 규칙: 해요체, 입력에 있는 숫자만, 사라/사지 마라 단정 금지, 종목 추천·수익 예측·대출 권유 금지, JSON 하나만 출력.

## 3. 구조
```
화면 ──useAi / runAi──▶ src/lib/ai/index.ts
                           │ VITE_AI_MODE=live ?
                           ├─ yes ─▶ POST /api/ai/:task ─▶ server/lib/ai.ts runAiTask
                           │                                  ├ AI_PROMPTS[task] + buildUserMessage
                           │                                  ├ Anthropic Messages API
                           │                                  └ JSON 파싱 + numbersGrounded 검사
                           │           실패(키 없음·형식 오류·지어낸 숫자) → 503
                           └─ no / 실패 ─▶ src/lib/ai/example.ts (예시 응답)
```
- **예시 응답도 내 데이터로 만든다.** 템플릿에 실제 숫자를 넣고, 카드 문자는 정규식 + 키워드 분류로 읽는다. 그래서 연결 전에도 화면이 사용자마다 다르게 보이고, 데모·발표가 가능하다.
- 예시 응답은 모델처럼 0.1~0.7초 기다렸다가 답한다(로딩 화면 흐름을 실제와 같게). 화면에는 "예시 AI 응답이에요"를 표시한다.
- 실제 모델로 바꾸는 방법: 서버에 `ANTHROPIC_API_KEY`(선택: `ANTHROPIC_MODEL`) 설정 → 빌드 때 `VITE_AI_MODE=live`. 화면 코드는 바꾸지 않는다.

## 4. 개발 흐름 (논문용 기록)
1. 기획 → 화면 → 계산 엔진(테스트 먼저) → 예시 데이터 순으로 개발.
2. AI 기능은 **입력·출력 계약(타입)을 먼저** 정하고, 예시 응답으로 화면을 완성한 뒤, 같은 계약으로 실제 모델을 붙인다. 모델이 바뀌어도(다른 회사·작은 모델·온디바이스) 계약만 지키면 된다.
3. 모든 예시 응답은 `tests/ai.test.ts`로 검증(조사 처리, 승인취소 제외, 누적금액 무시, 연도 넘김, 지어낸 숫자 차단 등).
4. 개발 자체에도 AI 코딩 도구를 썼다: 기획서·계산 규칙 문서화 → 테스트 작성 → 구현 → 375px 헤드리스 스크린샷 확인 → PR → 배포를 반복(`docs/night/LOG.md`에 세션별 기록).
