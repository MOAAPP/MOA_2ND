# 모아 기획서 29쪽 전기능 추적표 · 기술 제거 금지

기준: 2026-10-29 작성 「모아 기획서: 20대의 필수결제 자금 부족을 미리 알려주는 AI」 29쪽.
이 문서의 '구현'은 현재 저장소 코드가 있다는 뜻이지, 외부 실데이터·운영 인증정보·백테스트 성능이 검증됐다는 뜻이 아니다.

## 흔들리지 않는 제품 정의
- 공모전 핵심: **7~14일 안에 다가오는 필수결제일의 단일 결제계좌 잔액 부족 탐지**.
- AI 기술을 삭제하거나 'AI 브리핑 카드 하나'로 축소하지 않는다. **LLM 이해 → ML 변동 지출 예측(채택 조건 충족 시) → 정확한 코드 잔고 계산 → 규칙 알림 + LLM 설명**이 하나의 제품 파이프라인이다.
- 가상 평행세계, 예·적금, 모의투자, 교육, 시장 정보, 카드뉴스도 코드에서 제거하지 않는다. 기획서 26쪽은 이들을 후속 단계로 배치할 뿐 기술 삭제를 지시하지 않는다.
- 사용자가 처음 보는 화면은 결제일 위험, 위험이 생긴 이유, 어떤 데이터/모델을 썼는지, AI로 문자를 기록하는 행동을 즉시 보여준다. 개발자용 S01 날짜 조작은 설정으로 옮긴다.
- AI가 계산된 숫자를 생성하거나 임의로 바꾸지 않는다. **예시 템플릿은 실제 LLM 호출과 구분**하여 표시한다.

## 이번 UX 변경으로 실제 반영한 것
1. 개발자용 `가상 체험 · S01 / 날짜 ‹› / 관측된 합성 기록` 설명을 홈에서 제거하되, 날짜 이동 및 합성 고지는 **설정**에 보존.
2. 결제일 경고 바로 다음에 `CashflowCoach` 노출: LLM 설명과 **실제 LLM / 대체 템플릿** 라벨 구분, 지출 예측 방법 **기준선 / 채택 ML / 확정 일정** 표시, 잔액은 기존 결정적 엔진에 맡긴다.
3. 홈에서 `결제 문자를 AI로 자동 기록하기` → `Ledger`의 `PasteFlow`로 바로 연결. 검증 없이 자동 저장하지 않음.
4. 결제일 상세의 30일 그래프와 전체 계산 근거는 **탭이 있는 바텀시트**로 전환. 기존 자료·시나리오 계산은 삭제하지 않음. 위험 판단은 14일, 30일은 참고 그래프로 정확하게 분리.
5. 차트에 최소·최대 잔액 표기와 가까운 결제일의 날짜 라벨 교대 표시.
6. 결제 문자 분석 화면도 `appDay`를 사용하여 시연 날짜와 불일치하지 않게 수정.

## 공모전에서 인정받을 AI 증거, 남겨둔 과제
- 첫째: **LLM 추출 실제 호출을 확인**하고 은행·카드 문자 최소 50형식에서 정규식 파서와 날짜·금액·결제수단 추출 정확도를 비교한다. 마스킹 후 원문 로그/누출률도 검증한다.
- 둘째: **ML 채택 여부는 평가로 결정**한다. `adopt_ml=false`를 숨기지 않는다. LightGBM 결과가 두 기준선보다 우수할 때만 API로 결제일 예측에 연결한다.
- 셋째: **위험 알림 운영 파이프라인**은 앱이 닫혔을 때 발송할 저장소·동의·Cron/Push가 필요하다. 현재 투자 카드뉴스 스케줄러는 이를 대체하지 않는다.
- 넷째: 주간 결제일 Discord 리포트, 영수증 OCR/비전, Supabase RLS/실데이터 시범운영, 이용자 5~8명 검증은 별도 구현/실증이 필요하다.
- 전 기능·연구 요구사항은 남긴다. UI에서 숨기는 것은 '기술'이 아니라 **개발자용 시연 제어 텍스트와 과도한 펼침 UI**뿐이다.
