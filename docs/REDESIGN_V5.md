# 평행통장 v5 · 정보 구조 및 UI 개선 기록

## 핵심 가치 제안

**지난 선택을 돌아보고, 다음 선택의 미래를 먼저 경험한다.**

- 과거: 기록된 소비의 실제 선택과 다른 선택을 나란히 비교한다.
- 미래: 사기 전에 구매/보류/연기/대체 상품의 월말 예상 잔고를 비교한다.
- 개인화: 소비 기록에 기반한 지출 패턴·예측 품질을 별도의 소비 분석에서 제공한다.
- 실행·학습: 금융 개념→중간 퀴즈→피드백→실습을 유지하고, 모의투자는 독립 탭으로 제공한다.

## 사용자 플로우

1. 홈 → 현재 잔고 → **과거로** 또는 **미래로** 즉시 이동. 불필요한 중간 소개 화면 제거.
2. 과거 돌아보기 → 선택 기록 클릭 → 그날 실제 선택 vs 다른 선택의 **오늘까지 유출된 지출 차이** → 필요 시 기록 상세 확인.
3. 미래 미리 보기 → 이름(선택), 금액 입력 → **한 달 뒤 구매 vs 다른 선택** 두 숫자와 차이 확인 → 기록 저장 또는 더 자세히 보기.
4. 하단 평행세계 탭 → `지난 선택 · 과거` / `앞으로 · 미래` 전환.
5. 모의투자 · 금융 학습은 각각 하단 메뉴에서 독립 접근.

## UI 개선 원칙

- 상단 앱 바와 본문 배경·패딩·간격 일치, 모바일 전체 폭으로 이어지는 헤더.
- 1화면 1주요 목표: 잔고, 두 갈래 선택 카드, 월말 예상 잔고 순서.
- 카드 강조를 최소화하고 핵심 금액만 크게 표시.
- 소비 결과에서 중복 설명 배너/그래프는 제거; 날짜별 상세 그래프와 위험은 `<details>`로 이동.
- 대형 장식 이미지와 단계 이동 설명을 줄이고, 버튼의 실제 행동을 명시.

## 데이터 해석 및 유의 사항

- 과거 비교는 `choiceFlows`로 같은 기록의 실제 선택과 대안 선택을 재계산한 **지출액 차이**이다. 은행 API와 연동하지 않으며 과거 실제 계좌 잔고를 복원하지 않는다.
- 할부는 **오늘까지 도래한 할부 회차**만 과거 지출 비교에 반영한다. 미래 회차는 포함하지 않는다.
- 과거 선택 당시 입력한 현금·결제 기록이 부족하면 그 인과적 효과를 확정적으로 표현하지 않는다.
- 미래 예측은 사용자가 등록한 잔고·수입·지출에 기반한 시뮬레이션이며 투자 수익률 보장은 없다.
- ML 개인화·검증은 이전 v3에서 구현한 기기 내 모델을 유지했다. 이 v5 UI 작업에서 고도화된 새로운 모델을 학습한 것은 아니다.

## 파일 변경

- `src/screens/Home.tsx`: 잔고, 과거·미래 2갈래, 월말 예상 잔고, 추가 기능 목록.
- `src/screens/Past.tsx`: 신규 과거 회고 기능 및 인터랙션.
- `src/screens/Forks.tsx`: 과거·미래 세그먼트가 있는 중심 탭.
- `src/screens/Decide.tsx`: 단순한 문구, 중복 차트 상세로 이동.
- `src/App.tsx`, `src/state/nav.tsx`: 과거 회고 라우팅, 내비게이션 라벨.
- `src/ux-v5.css`, `src/main.tsx`: 스타일 토큰 및 공통 레이아웃.
- `build_preview.cjs`: 오프라인 미리보기용 이벤트 스트림 비활성화, 저장소 접근 제한 시 메모리 대체.

## 검증

- `npm run typecheck` 통과
- 오프라인 HTML Chromium 모바일 390px: 홈/과거/미래/미리 비교/상세 그래프/학습 퀴즈/모의투자/설정 이동 확인.
- 새 소비 5,800원 시나리오 결과 금액 차이와 퀴즈 보기 렌더링 확인.
- 모바일 390px에서 상단 앱바 너비 390px, 가로 오버플로 없음.
- **실제 서버 연동, 타 기기 배포 및 결제/실거래 연동은 완료·검증하지 않음.**

## 실행

1. Node.js 20+ 환경에서 `npm install`
2. `npm run dev`
3. 별도 다운로드한 `평행통장_v5_전체앱_클릭미리보기.html`은 브라우저에서 앱 화면을 빠르게 확인하기 위한 예시 데이터 포함 독립 파일이다. 실시간 시세 API 및 서버 기능은 온라인 서버가 필요하다.
