# 평행통장 3차 UX·기획 수정 (2026-10-20)

## 핵심 가치 제안
**오늘의 소비 결정을 입력 → 같은 조건에서 다른 선택을 비교 → 개인 소비 패턴을 반영한 예측/검증 → 선택과 결과를 기록 → 필요한 금융 개념을 퀴즈/모의투자로 학습**하는 금융 의사결정 도구. 실제 금융계좌 연동이나 수익 보장 서비스가 아니다.

## 정보 구조 및 화면 동선

- 최초 방문: **온보딩 5장** → 재무정보 입력 → 홈. 미리보기에는 강제 온보딩 전용 HTML을 분리했다. 저장된 데이터는 수정하지 않는다.
- 홈: 현재 잔고와 행동 2개(**사기 전 비교**, **쓴 돈 기록**) → **나의 소비 패턴 예측** → 목표 → 월말 예상 잔고. 두 선택의 돈 차이를 먼저 보여주고 그래프는 접힌 심화 정보.
- 소비 비교: 품목·금액 → 지금 구매 vs 보류/미루기/저렴한 대안 → **한 달 뒤 두 잔고, 차이** → 선택 저장. 모델의 역할(기본/기기 내/외부)은 별도 링크에서 설명. 소비 전/후 만족도, 지난 선택, 목표 연동은 기존 로직 유지.
- 모의투자: 하단의 독립 메뉴. 실제 투자·생활비와 분리된 가상 자금, 종목/ETF, 주문/포트폴리오/체결/카드뉴스는 그대로 유지.
- 금융 학습: 하단 독립 메뉴. **주제 타일(6개) → 레슨(24개 중 선택) → 개념 → 중간 퀴즈 → 해설 → 실습**. 레슨 진입 잠금 제거, 퀴즈·재도전·정답 데이터·진도 유지, 일일 퀴즈. 듀오링고식 긴 게임화 경로와 단순 '읽었어요'형 학습을 메인 흐름에서 제외.
- 설정: 상단 바를 full-bleed로 통일, 소개 다시 보기 → 완료 시 이전 설정 스택이 남는 오류 수정.

## 실제로 추가한 ML 기능 — 구현됨

`src/lib/ml/personalModel.ts`에 온디바이스 소형 지도학습 모델 추가:

1. 최근 최대 90일의 변동지출 기록을 날짜별로 모은다. 거래 미입력일을 0원으로 간주하므로 기록 누락이 많은 경우 정확도에 한계가 있다.
2. 28일 이상 기록 + 최소 14건이면 `요일 더미 변수(기준 요일=일요일) + 시간 추세`를 사용한 **L2 릿지 회귀**를 브라우저에서 학습한다. 최근 관측일에 가중치를 준다.
3. 반드시 **마지막 7~14일을 시간순으로 분리해 검증**한다. 기본 훈련 평균 예측과 MAE(평균 절대오차)를 같은 기간 비교한다.
4. 모델 MAE가 기본 MAE보다 **최소 5% 작을 때만** `SpendingForecast.engine = 'local'`로 활성화한다. 그렇지 않으면 기존 규칙 기반 예측이 계속 사용된다. 서버 모델이 있으면 API 예측이 우선이며 네트워크 오류 시 로컬/기본으로 자동 복귀.
5. 학습이 적용되면 날짜별 예상 생활비(p10/p50/p90)를 기존 현금흐름 위험 시뮬레이션에 연동한다. 범위는 경험적인 잔차 크기 기반의 **거친 추정 범위**이며 통계적 80% 보장 구간이 아니다.
6. **내 소비 분석** 화면에서 데이터량, 가장 큰 지출 분류, 주간 지출 추정, 시간순 검증 기간, 모델 MAE와 기본 MAE, 채택 사유를 볼 수 있다.

**정확성·프라이버시 주의:** 기록이 적을 때는 ML 사용 중이라고 표시하지 않는다. 데모 데이터도 '예시 통장'으로 구분한다. 브라우저 내 학습만 사용하는 경우 데이터를 외부 서버로 보내지 않는다. 서버 예측을 `VITE_ML_API_URL`로 연결하면 해당 요청에는 기록이 포함될 수 있다. 모델은 금융 자문/실제 시세 예측 기능이 아니다.

## ML 팀원의 다음 확장 제안 — 아직 구현되지 않음

- **카테고리 학습:** 사용자가 고친 품목 분류(`categoryMemory`)를 모아 TF-IDF / sentence embedding + 경량 분류기의 데이터로 활용. confidence < 0.6일 때 재확인 요청, 수정 후 점진적 재학습. 정확도·macro-F1 평가.
- **변동지출 예측:** `POST /forecast` API를 LightGBM 분위수 회귀(특성: 요일, 공휴일, 최근 소비 평균/변동성, 카테고리, 수입일까지 남은 일수 등)로 대체; 기본/온디바이스 모델 대비 rolling-window MAE 및 분위수 pinball loss 측정.
- **선택 추천:** 선택별 미래 잔고와 부족 확률·목표 달성 시점의 다목적 점수 계산. '미루면 얼마나 개선되는지'를 수치로 설명. 단순한 구매 강요나 검증되지 않은 개인화 추천은 금지.
- **학습 개인화:** 퀴즈 문항별 오답 주제를 추적해 미학습 내용 추천(현재는 주제별 자유 진입), 모의투자 성과를 실제 자산과 혼합하지 않기.
- **검증 및 협업:** 동일하게 정의된 평가 데이터셋에서 시간 기준 학습/검증 분리, 기록 누락/중복 분석, 드리프트 모니터링, 예측 로그 모델 버전 명시. 학습용 기록 업로드는 동의 기반으로 운영.

## 수정된 코드
- `src/App.tsx`: insights 라우트·5장 온보딩 강제 프리뷰·소개 완료 후 스택 초기화·학습 탭명
- `src/state/nav.tsx`: 개인 분석 화면 타입
- `src/screens/Intro.tsx`: ML 차별점 소개 페이지, 온보딩 다음/건너뛰기 정리
- `src/screens/Settings.tsx`: 기존 소개 다시 보기 유지; UI는 공통 헤더 CSS로 해결
- `src/screens/Home.tsx`, `src/screens/Decide.tsx`: 소비 분석 진입점
- `src/screens/Insights.tsx`: 새로운 ML 설명 가능 UI
- `src/screens/Learn.tsx`, `src/screens/Lesson.tsx`: 중간 퀴즈/복습/실습 복구, 기존 잠금 해제
- `src/lib/ml/personalModel.ts`, `provider.ts`, `types.ts`: 실제 학습, 검증, 폴백
- `src/ux-v3.css`: 공통 상단 바 및 새 화면 UI
- `build_preview.cjs`: 기능/온보딩 각각 오프라인 클릭형 HTML 미리보기
- `tests/checkPersonalModel.cjs`: 런타임 패키지 없이 실행 가능한 학습 모델 QA

## 실행 및 테스트
- `npm install` 다음 `npm run dev` (원래 서버·UI 모두 실행; 시세 API는 별도 설정 필요)
- `npm run typecheck`: 통과
- `node tests/checkPersonalModel.cjs`: 통과 (주말 패턴 검증 개선, 콜드스타트 폴백, 분위수 순서, 상수 데이터 폴백)
- 브라우저 실제 컴포넌트(모바일 390×844) 테스트: 5장 온보딩 → 홈, 홈 → ML 화면 → 홈, 홈 → 설정 → 온보딩 재보기, 학습 → 개념 2개 → 중간 퀴즈 선택 및 정답 확인, 공통 헤더 폭 확인 / JS 예외 없음.
- `npm test`/`vite build`: 이 작업 환경에 **리눅스용 Rollup 네이티브 패키지 미설치**로 실행 불가. 별도 Linux/Windows/macOS에서 깨끗하게 `npm install` 또는 `npm ci`로 재설치하여 검증 필요. 서버/실제 주가/Discord/OCR 등의 API 통합 테스트는 여기서 수행하지 못함.
