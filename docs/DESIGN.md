# 평행통장 설계 정리

> "내가 돈을 쓴 세계와 다른 선택을 한 세계의 미래를 나란히 보여준다."

## 1. 핵심 사용자 흐름

1. **소개 온보딩(3장)** → 건너뛰기/다음 → '평행통장 시작하기'
2. **초기 설정(한 화면 한 주제)** 잔고 → 들어올 돈 → 나갈 돈 → 지켜둘 금액 → 목표(선택) → 오늘 일정 반영 확인(해당 시) → 월말 예상 잔고 → '첫 소비 비교하기'
3. **사기 전 확인** 금액·카테고리·날짜 → 두 세계(산 나 / 안 산 나) → 필요 시 미룬 나·대안·할부 열기 → 날짜 슬라이더로 두 세계 동시 이동 → '이렇게 할게요'로 선택 기록
4. **갈림길** 기록 다시 보기(당시 결과 vs 최신 재계산) · 선택/만족도 수정 · 평행세계 포함 토글 · 회고
5. **미래** 목표·월 저축액 → 현재 패턴의 나 vs 선택을 바꾼 나(빈도·기간·이자 가정 표시)
6. **배움** 지식 진단 → 종목 검색 → 상세 → 모의 주문 → 체결 → 보유/매도 → 카드뉴스 4장 생성 → Discord 전송/재시도

## 2. 화면 목록

| 영역 | 화면 |
|---|---|
| 시작 | 소개 3장, 초기 설정 6단계, 설정 결과 |
| 통장(탭1) | 홈: 현실 잔고·평행 잔고·차이·월말·가까운 필수지출·최소잔고 경고 / 사기 전 확인 / 이미 쓴 돈 기록 시트 |
| 갈림길(탭2) | 기록 목록·필터, 기록 상세(당시/최신), 회고 요약 |
| 미래(탭3) | 목표 카드, 두 세계 도착 시점 비교, 가정 편집 |
| 배움(탭4) | 진단, 종목 목록·검색·관심, 종목 상세, 주문 시트·확인·결과, 보유·주문·거래 내역, 카드뉴스 목록·뷰어, Discord 연결 |
| 설정(상단) | 재무 정보 수정·잔고 갱신, 움직임 줄이기, 소개 다시 보기, Discord 상태, 데이터 초기화(범위별) |

하단 메뉴는 모든 화면에서 **통장 · 갈림길 · 미래 · 배움** 순서로 고정.

## 3. 디자인 방향

- 밝은 배경(#F3F5F8), 짙은 글자(#151A22), 주요 액션 블루(#2563EB)
- **현실** = 실선 + ● 라벨 "현실", 짙은 남색 / **평행** = 점선 + ◇ 라벨 "평행", 절제된 보라. 색 외에 선 모양·기호·문구로 구분
- 가정한 금액은 항상 "평행" 라벨과 점선 테두리, "가정" 표시
- 갈라짐 그래프: 같은 시작점에서 두 선이 갈라지고, 날짜 슬라이더가 두 세계를 같은 날짜로 함께 이동
- 애니메이션은 선이 갈라지는 순간·숫자 전환에만 사용, `prefers-reduced-motion`과 앱 내 '움직임 줄이기' 설정 모두 존중
- Pretendard, 금액은 tabular-nums, 버튼 높이 52px 이상, 하단 고정 버튼은 safe-area + 키보드 높이(visualViewport) 반영

## 4. 데이터 계산 기준 (src/lib, shared/ 의 코드로만 계산 — AI 미사용)

### 기준 잔고
- 사용자가 입력한 잔고는 **기준일(baseDate)·입력 시각** 시점의 금액.
- 기준일 이전 날짜의 일정은 이미 반영된 것으로 보고 시뮬레이션하지 않음.
- 기준일 **당일** 일정은 설정 마지막에 "이미 통장에 반영됐나요?"를 물어 항목별로 결정.
- 오늘이 기준일보다 뒤면 "지금 잔고"는 *기준 잔고 + 그 사이 일정*으로 계산한 **예상치**이며 그렇게 표시. 7일 이상 지나면 잔고 갱신 안내.

### 날짜별 잔고
- `잔고(d) = 잔고(d-1) − 지출(d) + 수입(d)`
- **같은 날 수입·지출이 함께 있으면 지출을 먼저 빼고 수입을 더함(보수적)**. 그래서 하루 중 최저점도 '가장 낮은 잔고'에 포함.
- 매월 반복 일정의 날짜가 그 달에 없으면(예: 31일, '말일') **그 달의 마지막 날**로 처리.
- 모든 시나리오는 같은 시작 잔고·공통 일정에서 출발하고, **선택 때문에 달라진 거래만** 다르게 반영.

### 선택별 거래
| 선택 | 반영 |
|---|---|
| 산다 | 구매일에 −금액 (할부면 구매일부터 매월 같은 날 n회, 나머지 원은 1회차에) |
| 안 산다 | 거래 없음 |
| 미룬다 | 미룬 날짜에 −금액 (사라지지 않음). 미룬 날이 다음 달이고 반복 수입이 없으면 '불확실' 표시 |
| 대안 | 구매일에 −대안 금액 |

### 이미 쓴 돈(중복 차감 방지)
- 거래마다 `잔고에 이미 반영됨` 여부를 가짐. 기본값: 기준일보다 이전이면 반영됨, 기준 잔고 입력 이후 기록이면 반영 안 됨. 사용자가 바꿀 수 있음.
- 반영된 거래는 현실 시뮬레이션에서 다시 빼지 않음.
- 잔고를 새로 입력하면 그 이전 거래는 모두 '반영됨'으로 바뀜.

### 평행세계
- `평행 = 현실 + Σ(델타)` , `델타 = 다른 선택의 거래 − 실제 선택의 거래`
- 델타는 **기록 ID당 한 번만** 적용 → 같은 소비를 여러 번 되돌리지 않음.
- 사용자가 '평행세계에 넣기'로 고른 기록만 포함(자동 포함 없음).
- 다른 선택의 기본값: 샀다 → 안 샀다면, 안 샀다 → 샀다면, 미뤘다·대안 → 지금 (원래 것을) 샀다면. 기록 상세에서 변경 가능. (평행세계가 항상 더 부유하지 않음)

### '며칠 더 여유'
- 두 세계에서 잔고가 최소 잔고(또는 0) 아래로 처음 내려가는 날짜를 비교해, 둘 다 기간 안에 있을 때만 일수 차이를 표시. 하루 생활비로 나누는 계산은 하지 않음.

### 목표
- 월 저축액(사용자 입력)으로 매월 1회 적립, 선택 이자율(연, 월복리, 기본 0%).
- 평행 시나리오: 한 번 / 매주(월 52/12회 환산 대신 실제 주 수를 개월 단위로 누적) / 매달, 기간(개월)을 명시.
- "예상"·"가정"으로만 표현, 보장 문구 없음.

### 모의투자
- 생활비와 분리된 모의 자금 10,000,000원(설정에서 초기화 가능).
- 시장가: 장중에만, 확인 화면에 보인 시세로 체결. 장 밖에서는 지정가 예약만 가능.
- 지정가: 매수는 주문금액만큼 현금 예약, 매도는 수량 예약. 취소·만료 시 예약 해제.
  - 체결 규칙(단순화): 주문 유효 거래일의 **관측된 가격 범위**(현재가·당일 저가/고가)가 지정가에 닿으면 **지정가로 체결**. 매수는 저가 ≤ 지정가, 매도는 고가 ≥ 지정가.
  - 주문은 해당 거래일 장 마감 후 미체결이면 만료(장 밖에서 낸 주문은 다음 거래일 유효).
  - 앱이 열려 있을 때 시세를 확인하면서 판단(서버에 주문을 저장하지 않음).
- 수수료·세금 **미반영**(화면에 표시).
- 주문 ID는 확인 시트를 열 때 만들고, 같은 ID는 한 번만 처리 → 중복 클릭 방지.

### 카드뉴스
- 체결 직후 서버에 작업 생성(거래 ID로 멱등) → 시세·과거 일봉·기사·사진 수집 → 4장 PNG(1080×1350) 렌더 → 자동 전송 설정 시 Discord 첨부 4장 전송.
- 상태: 생성 중 / 전송 중 / 전송 완료 / 실패(생성 단계·전송 단계 구분) / 재시도 가능.
- 자동 전송은 작업당 1회. 다시 보내기는 사용자가 누를 때만.

## 5. 2차 개편 (2026-10-17)

### 배움 탭 = 단계별 학습 + 모의투자 연습장
- 상단: 연속 학습일 · XP · 설명 수준
- [단계별 학습] 레벨테스트 → 이어서 하기 → 오늘의 카드뉴스 → 오늘의 퀴즈 → 6단원 학습 경로
- [모의투자 연습장] 지수 띠(장 상태·코스피·시세 출처 배지), 모의 자산, 종목 검색·관심·실시간 갱신 목록
- 전체 커리큘럼: `docs/CURRICULUM.md`

### 카드뉴스 = 매일 앱으로 돌아오게 만드는 요소
- 보내기 버튼 없음. 데일리는 서버 스케줄러가 정해진 시각에, 체결 카드는 체결 직후 자동.
- 사용자가 누를 수 있는 건 실패했을 때의 '지금 다시 시도'뿐(거래 ID·날짜로 중복 전송 방지).
- 4장 구성: 시장 → 내 종목 → 왜 움직였을까 → 오늘의 한 걸음(퀴즈·다음 레슨·연속 학습).

### 실시간 시세
- KIS 웹소켓(체결 즉시) → KIS REST/네이버(3초) → Yahoo(지연) 자동 전환, 화면은 SSE로 갱신.
- 배지: '실시간 체결' / '네이버·자동 갱신' / '지연 시세' / '예시 시세'.
