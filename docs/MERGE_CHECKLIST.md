# 평행통장 — 프론트/백엔드 통합 테스트 및 main 병합 체크리스트

> **코드 병합 전:** 아래 항목을 실제 브라우저 및 배포 미리보기에서 확인한다.
> 개발 브랜치에 있는 기능은 `main` 또는 운영 서버에 아직 포함되지 않을 수 있다.

## 브랜치 및 검증 범위
- 프론트: `MOAAPP/MOA_2ND` → `feat/world-agent-frontend-integration`
- 백엔드: `MOAAPP/MOA_2ND_BE` → `feat/personal-input-integration`
- `.github/workflows/validate-agent-backend-frontend.yml`: 프론트 빌드/순수 변환/디자인 불변 검사
- `.github/workflows/live-fastapi-contract.yml`: **백엔드 해당 브랜치를 별도로 체크아웃하고 로컬 HTTP 서버를 실행하는 진짜 양쪽 계약 테스트**. 운영 EC2/Vercel 연결 또는 화면 클릭 테스트가 아님.
- 실제 화면 파일보다 `releases/MOA_home_dashboard_ai_20261115.zip`이 배포 빌드 원본이다. 빌드 스크립트가 테스트한 패치를 ZIP에 적용하는지 확인.

## 수동 테스트 — 프론트 원래 디자인 변경 금지
- [ ] 프론트 해당 브랜치의 프리뷰 링크 열고 홈/가계부/평행세계/3D/저축/투자/Agent의 레이아웃과 모바일 폭 비교.
- [ ] `/demo` 홈: API S01 통장 잔액과 일치. **42만 원으로 고정된 예시가 뜨면 연동 실패.**
- [ ] `/demo` 가계부: S01 거래만 나오며 카드값을 중복 합산하지 않음.
- [ ] Agent에서 S08 선택: 홈/가계부/Agent가 모두 S08 기준. S01 거래가 남지 않음.
- [ ] 산 나/안 산 나: 7일·30일·90일 모두 진짜 API 수치 표시, 응답 실패 시 가짜 분석 표시 안 함.
- [ ] 3D 여섯 세계선: 기존 1~10년 그래프 그대로. '진단' 버튼의 90일 결제계좌 안전성은 Python API 기준. 3/6개월 연기는 90일 검증 범위 제한 안내.
- [ ] 가상 적금: 3/6/12개월 백엔드 만기액/90일 위험 표시. 24개월 지원 제한 안내. 가상 가입/행성 성장 레이아웃 정상.
- [ ] 모의 ETF: 체결 시 백엔드 90일 위험 안내, 별도 모의 투자금과 실제 결제계좌를 합치지 않음.
- [ ] `/` 일반 사용자: 임의의 (실제 개인정보 아닌) 잔액/월급/월세 입력 → 본인 기준 평행세계 결과. S01/S08 응답이 절대 표시되지 않음.
- [ ] 일반 사용자: 전송 동의 거절 시 서버 요청 없이 앱 내부 계산이라고 표시.
- [ ] 일반 사용자: 비정상 금액, 느린 응답, 네트워크 오류 시 S01 예시 결과로 대체하지 않음.
- [ ] 일반 사용자 목표 분석은 현재 **LLM이 아닌 Python 규칙 기반 분석**이라고 안내.
- [ ] 새로고침/화면 재진입/S01↔S08 변경에도 데이터가 섞이지 않음.
- [ ] Vercel 브라우저 Network 탭에서 `/api/v4/*` 요청 상태 200과 `X-MOA-Backend` 응답 헤더 확인. `legacy-compat`면 최신 백엔드가 아님.

## 배포/보안 환경 점검 (병합 전에 확인)
- [ ] Vercel의 서버 측 `MOA_PROXY_SHARED_KEY` 설정 (클라이언트 `VITE_*` 접두어 금지).
- [ ] `MOA_FASTAPI_ORIGIN` = **HTTPS 최신 백엔드** 주소. EC2의 배포 SHA에 새 `/api/v4/personal/*` 라우트 포함.
- [ ] 백엔드 `MOA_REQUIRE_GATEWAY=1`, `MOA_GATEWAY_SECRET` = Vercel `MOA_PROXY_SHARED_KEY`과 일치.
- [ ] 백엔드 `MOA_DEPLOYMENT_MODE=production`. 보호 게이트웨이 미설정이면 개인 입력 API는 안전하게 503 반환해야 함.
- [ ] CORS, 429(사용량), 502(연결 장애), 503(보안 게이트웨이 미설정) 상황 테스트.
- [ ] 테스트에는 실제 금융·신원 데이터 사용하지 말고 임의의 금액만 사용할 것.
- [ ] `main` 직접 push 없이 PR diff 리뷰 후 병합.

## 권장 병합/배포 순서
1. 두 브랜치의 GitHub Actions 검사 통과 + 위 브라우저 확인을 완료.
2. **백엔드 PR 먼저 병합**하여 최신 FastAPI 서버에 배포. 새 라우트와 헬스 체크 확인.
3. Vercel 서버 전용 게이트웨이 환경값 설정·검증. `legacy-compat` 응답이 나오면 프론트 병합 금지.
4. **프론트 PR 병합**하여 Vercel 배포. 배포 직후 `/demo`, `/` 요청과 오류 처리 회귀 테스트.
5. 실패하면 해당 배포 롤백. 기존 UI 디자인은 변경하지 않기.

**현재 자동화된 통합 테스트는 로컬 FastAPI 프로세스까지 검증하지만, 실제 EC2↔Vercel 배포 네트워크 및 브라우저 사용자 조작은 확인하지 않는다.**
