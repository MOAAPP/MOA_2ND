# MOA 금융 AI v10 — 품질, 모니터링, 성능 평가

## 목적과 범위

평행통장의 사용자용 설명을 존댓말로 일관되게 만들고, 금융 엔진의 계산 결과를 근거로 **왜 이런 판단인지, 어떤 위험이 있는지, 무엇을 확인하면 되는지** 설명한다.

운영 앱은 `moa-app`이고, Node API(`/api/ai/brief`, `/api/ai/coach`, `/api/ai/ledgerSummary`)는 `shared/aiPrompts.ts`의 10단계 검토 프롬프트를 사용한다. 별도의 FastAPI에서는 금융 브리핑·금융 학습 퀴즈에 동일한 품질 기준을 적용한다.

10단계는 **출력 전 검토 기준 10개**로, 모델을 10번 호출하거나 실제로 10단계의 독립 에이전트를 동작시킨다는 뜻이 아니다. 재무 계산은 기존 TypeScript·Python 엔진이 담당하고 LLM은 검증된 결과를 해석한다.

## 응답 품질 기준

1. 질문 목적을 분류한다.
2. 관측 데이터, 계산 결과, 미확인 정보를 구분한다.
3. 월세·카드대금·생활비 안전선을 보호한다.
4. 사용 가능 금액과 미래 계좌 최저 잔액을 구별한다.
5. 확인된 결제일과 기간만 이용한다.
6. 선택과 보류 등의 검증 가능한 대안을 검토한다.
7. 제공된 기록에서만 소비 습관 신호를 찾는다.
8. 예측 불확실성과 현금 부족을 구별한다.
9. 바로 실행할 확인 행동 하나를 제시한다.
10. 근거 → 영향 → 다음 행동 순으로 자연스러운 존댓말로 설명한다.

### 생성 후 품질 검증

- JSON 스키마 검증, 임의 금액 생성 검사, 존댓말 문장 검사를 통과한 결과만 표시한다.
- 반말 응답이면 최대 1회 재생성한다. 다시 실패하면 사용자에게 AI 응답을 노출하지 않고 규칙 기반 분석으로 대체한다.
- 프론트엔드 예시 분석과 실제 LLM 응답은 혼동되지 않도록 별도 표시한다.
- 단순히 구매를 미루면 안전하다고 보장하지 않는다. 결제일이나 잔액이 확인되지 않았다면 확인이 필요하다고 설명한다.

## 운영 모니터링 (현재 구현 범위)

| 지표 | 정의 | 위치 |
|---|---|---|
| 응답 성공률 | 검증된 AI 응답 / 요청 수 | `aiStats()`, 구조화 로그 |
| 실패 원인 | network, http_error, no_json, invalid_output, ungrounded, impolite 등 | Node 코드값만 기록 |
| 처리 시간 | 작업별 평균 응답 시간 및 최근 200개 표본의 p95 | Node `aiStats()` |
| 백엔드 처리 시간 | Python 모델 호출의 성공/오류 코드 및 처리 시간 | `moa_ai_provider_request` 로그 |
| 존댓말 준수 | 문체 검증 통과 건수 / 유효 응답 건수 | 오프라인 테스트·라이브 벤치마크 |
| 금융 수치 근거 | 입력 수치 또는 계산된 값으로 뒷받침되는 응답 | 스키마·수치 근거 검사 |
| 행동 제시 | 확인·비교·보류 등 다음 행동 포함 여부 | 벤치마크 휴리스틱, 수동 검토 필요 |

**개인정보 보호:** 모니터링 로그에는 사용자 ID, 질문 원문, 거래명, 잔액, API 키를 남기지 않는다. 작업 유형, 성공 여부, 오류 코드, 처리 시간만 기록한다.

**운영 제약:** Node `aiStats()`는 서버리스 인스턴스의 일시적 메모리 통계이며 전체 요청의 장기 집계가 아니다. 구조화 로그를 별도 로그 수집 서비스/대시보드에 연결해야 지속적 추적과 알림이 가능하다.

## 테스트

```bash
npm ci
npm run typecheck
npx vitest run tests/aiQualityV10.test.ts tests/ai.test.ts tests/aiSchemas.test.ts
bash scripts/build-moa-app.sh
```

CI: `.github/workflows/finance-ai-v10.yml`

실제 모델의 단일 요청 성공률 및 응답 시간은 **별도 스테이징 환경에서만** 검증한다.

```bash
MOA_AI_BENCH_URL=https://YOUR-STAGING-DOMAIN npx tsx scripts/eval/finance-ai-live.ts
```

벤치마크는 개인정보 없는 **합성 소비 사례 8개**를 순차적으로 요청하고 `reports/finance-ai-live.json`에 p50/p95, 스키마 통과율, 존댓말 준수율, 금액 근거 통과율, 행동 제시 휴리스틱 통과율을 기록한다. CI의 수동 실행에서도 URL을 지정할 수 있다. 실제 모델 비용이 발생할 수 있다.

## 품질 개선 전후 비교 및 공모전 표현

현재 자동화는 코드 수준의 회귀 테스트와 **향후 라이브 성능을 측정할 수 있는 벤치마크**를 제공한다. 이 작업만으로 '정확도 30% 향상', 'AI 응답속도 2배 개선', '금융 조언 정확성 입증'을 주장해서는 안 된다.

공모전/발표용 권장 표현:
> 기존의 단순 문장 생성 프롬프트를 금융 맥락 검토 10단계로 재구성하고, 계산 엔진의 수치 검증, 존댓말 품질 게이트, 재생성, 익명화된 지연 시간·오류 모니터링과 합성 사례 기반 회귀 테스트를 적용했습니다.

실제 라이브 성능 비교 수치는 이전/변경 버전의 동일 데이터셋·동일 모델·동일 조건으로 수행한 결과가 확보되면 별도로 추가한다. 자동 테스트 통과는 인간 전문가에 의한 재무 조언 검증을 대체하지 않는다.
